# 動畫去背工作臺：新手教學

本教學對照 **v3.12.0**。先完成一支短片，再用同一套一鍵修復流程處理多表情動畫。

[回到 README](../README.md) · [下載發布版](https://github.com/wen880225/animation-workbench/releases/latest) · [完整使用說明](../使用說明.txt) · [依賴與限制](../依賴與限制.txt)

## 1. 先確認你需要準備什麼

這是 **Windows 原始碼套件，並非免安裝 EXE**。工作臺提供操作介面與修整功能，影片去背交由本機 ComfyUI 執行。

| 必需項目 | 用途與準備方式 |
| --- | --- |
| Windows x64 | 此分享版的目標平台；使用可寫入的資料夾。 |
| Python 3.12 x64 | 安裝時保留 Python Launcher（`py`）；安裝腳本會建立工具專用的 `.venv`。 |
| FFmpeg 與 FFprobe | 拆解影片及輸出 WebM；需要 `libvpx-vp9` 編碼器與解碼器。 |
| 本機 ComfyUI | 必須包含隨附 `qwen_original.json` 固定工作流所需的節點，並另行備妥相容模型。 |
| NVIDIA GPU + CUDA PyTorch + RIFE 4.25 | 一鍵接縫修復需要；獨立於 ComfyUI，依[模型安裝教學](model-setup.zh-TW.md)準備。 |
| 磁碟空間 | 會保存影片、拆幀、透明 PNG 及每次另存版本；先用短片估計用量。 |

Python 可從 [Python Windows 官方下載頁](https://www.python.org/downloads/windows/) 取得；FFmpeg 請從 [FFmpeg 官方下載入口](https://ffmpeg.org/download.html) 選擇 Windows 套件；ComfyUI 請參考 [ComfyUI 官方專案](https://github.com/Comfy-Org/ComfyUI)。

**已安裝 ComfyUI，不代表所需工作流已能執行。** 目前工作流指定的模型名稱為：

| 模型選單 | 所需檔名 | 放入 ComfyUI 的資料夾 |
| --- | --- | --- |
| UNETLoader | `qwen_image_2.1_int8_convrot.safetensors` | `models/diffusion_models` |
| CLIPLoader | `qwen3vl_8b_int8_convrot.safetensors` | `models/text_encoders` |
| VAELoader | `qwen_image_2.1_vae_bf16.safetensors` | `models/vae` |

模型下載與放置位置請依 [Comfy-Org 官方模型文件](https://huggingface.co/Comfy-Org/Qwen-Image-2.1/blob/main/README.md)操作；模型不包含在分享套件中。不要把不相容模型重新命名來湊檔名。

完整節點清單見[依賴與限制](../依賴與限制.txt)。`QwenImage21Cache`／`TextEncodeQwenImage21`、`SaveImageAdvanced`、`ComfySwitchNode` 已可在 ComfyUI 官方本體找到，對應來源為 [Qwen 節點](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_qwen.py)、[圖片節點](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_images.py)、[邏輯節點](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_logic.py)。若環境檢查顯示缺少，請將 ComfyUI 更新到包含這些節點的版本並重新啟動，再檢查一次；本教學不指定尚未驗證的最低版本。只執行工作臺的 `setup.cmd` 不會補齊 ComfyUI 環境。

隨附工作流為 API 格式、節點編號固定，不是可任意替換工作流的匯入器。顯示卡、VRAM 與 RAM 需求取決於 ComfyUI 模型和設定，目前沒有已驗證的統一最低規格。

**工作臺的 MIT 授權不涵蓋模型。** Qwen Image 2.1 的官方授權限非商業研究／評估，商業使用需另向官方取得授權；模型使用條款和輸出素材權利要分別確認。使用前請閱讀 [Qwen 官方授權](https://huggingface.co/Qwen/Qwen-Image-2.1/blob/main/LICENSE)與[第三方說明](../THIRD_PARTY.md)。

## 2. 第一次安裝與啟動

1. 從 [v3.12.0 發布頁](https://github.com/wen880225/animation-workbench/releases/tag/v3.12.0)下載附件 `AnimationWorkbench_v3.12.0_source.zip`，完整解壓縮到例如 `D:\AnimationWorkbench`。進入可看見 `setup.cmd` 的資料夾；不要在 ZIP 或唯讀資料夾內執行。
2. 安裝 **Python 3.12 x64**，保留 Python Launcher。雙擊 `第一次安裝.cmd`，或同內容的 `setup.cmd`。此步需要網路，會在 `.venv` 安裝 NumPy、Pillow、SciPy 與 OpenCV；確切版本見 [requirements.txt](../requirements.txt)。看到安裝完成後再繼續。
3. 安裝 FFmpeg／FFprobe。可將它們加入 Windows 的 PATH，或把完整 FFmpeg 套件的 `bin` 內容放到 `D:\AnimationWorkbench\tools\ffmpeg\bin`。若下載的是 shared 版，相關 DLL 也必須保留，不能只複製兩個 EXE。
4. 啟動你已備妥模型與節點的 ComfyUI。工作臺預設連線到 `http://127.0.0.1:8188`；若你的 ComfyUI 使用其他本機埠號，稍後在介面修改。
5. 雙擊 `啟動工具.cmd`，或 `start.cmd`。在瀏覽器開啟 [本機工作臺](http://127.0.0.1:8767)，並確認右下角顯示 **v3.12.0**。舊服務仍在執行時，先保存並等處理結束，再執行 `重新啟動工作台.cmd`；只重新整理頁面不會更新後端。
6. 按左上角 **「＋ 匯入影片」**，展開 **「模型設定與環境檢查」**，確認 ComfyUI 位址，再按 **「檢查環境」**。依畫面訊息補齊模型、節點或 FFmpeg，再重新檢查。

7. 需要一鍵修復接點時，完成[本地 RIFE 模型安裝](model-setup.zh-TW.md)。去背環境檢查通過不代表 RIFE 已安裝。

環境檢查通過後，仍要完成下一節的短片試跑，才能確認模型實際執行與成品是否符合需求。安裝腳本不會代為安裝 ComfyUI、模型、FFmpeg 或顯示卡驅動。此版本只支援本機 ComfyUI（`localhost`／`127.0.0.1`），未提供多人登入服務。

## 3. 先用短片跑通一次，再批次處理

### 第一次去背

1. 準備一支容易判斷輪廓的短片，按 **「＋ 匯入影片」→「選擇影片…」**，或把影片拖進虛線框。
2. 在 **「套用到本次加入的影片」** 選 **「每支先試跑，之後逐一確認」**。介面預設是整段去背，第一次使用請主動改成試跑。
3. 展開 **「幀範圍與輸出設定」**。初次先讓 FPS 留白，起始幀保留 1；試跑預設連續 48 幀，也可改為你的一個短循環長度。幀就是動畫中的一張圖片。
4. 按 **「加入隊列並開始」**，等待試跑完成。從 **「任務隊列」** 按 **「檢查素材」** 開啟結果。
5. 在 **「播放檢查」** 看正常速度與慢速播放；再到 **「逐幀檢查」** 放大看邊緣、透明區和細節。檢查時切換深淺底色，容易發現漏去背或邊緣殘留。
6. 效果可接受後，按 **「確認效果，排入全片去背」**。若隊列已暫停，再按隊列上方的開始／繼續按鈕。若效果不合適，先調查模型與來源，不要直接送入大量長片。

「僅加入隊列」可先排好素材；隊列原本正在執行時，新任務仍會接在後面。暫停會保留已完成影格，但已送給 ComfyUI 的請求可能繼續完成。重新啟動工作臺後，需要手動繼續隊列。

### 一次匯入多支影片

短片成功後，同一個 **「選擇影片…」** 可多選，也可分次追加，一次最多 100 支。支援 MP4、MOV、MKV、WebM、AVI、M4V、OGV、GIF，實際能否解碼仍取決於 FFmpeg。

本次加入的影片共用幀範圍與模型設定；FPS 留白則各自沿用來源 FPS。改 FPS 也會改變幀編號。單支匯入或處理失敗不會阻擋其他有效影片；先閱讀該項原因再重試。所有輸出均無音軌。

## 4. 只要認識兩個工作區

- **素材檢查**：查看去背結果，切換播放或逐幀檢查。需要重跑某一幀時也在這裡處理。
- **接點修整**：單段的結尾接開頭、多段的上一段接下一段，都使用這裡。

字太小可到「顯示設定」切換大字。預覽選「符合視窗」會完整顯示圖片；100%／200% 用來查細節，超出視窗時可捲動。「專注畫布」可暫時收起設定欄。這些選項及檢查底色都不改變輸出。

## 5. 素材與順序

**單段循環：** 在素材檢查選擇已完成去背的任務，按「以目前素材建立修整」。它使用該任務的原始去背 PNG；不會因播放器選了舊版本，就偷偷改用舊版本繼續加工。

**多段動畫：** 進入接點修整，建立專案，批次勾選已完成的來源，再加入。清單中的「原始去背」與「修整版本」是不同來源；選修整版本會以其已輸出的 PNG 開始，不會再次套用舊方案。

每組來源必須有相同畫布寬高，最多 16 段。用上移／下移安排實際順序，再選路線：

| 路線 | 例子 | 要檢查的接點 |
| --- | --- | --- |
| 循環 | A → B → C → A | A→B、B→C、C→A |
| 依序播完 | A → B → C，然後停止 | A→B、B→C |
| 一段循環 | A → A | A 尾幀→A 首幀 |
| 一段依序播完 | A 播完停止 | 不必建立接點，可直接預覽與輸出 |

排序不是依檔名猜測。請核對顯示的路線。更換路線、來源或範圍後，需要重新修復；工具不會把開放序列的最後一段強制接回開頭。

## 6. 一鍵修復，再播放驗收

1. 進入 **「修復與驗收」**。若片段之間忽明忽暗，先展開「進階微調 → 進階：整組明暗與手動校準」，選基準片段並按「統一整組明暗」，完成後回到修復。明暗已一致可略過。
2. 按 **「一鍵修復全部接點」**；已有修復時顯示「重新修復全部接點」。不必先按分析，也不必再按安全套用。
3. 等待「量測整段比例 → 穩定整段比例 → 本地模型重建接縫」。工具會先補償整段微小放大／變寬，再重建相鄰片段的頭尾過渡；不是只在尾段縮回。
4. 完成後修復直接套用並儲存。看「整段比例」狀態，選接點按 **「0.1× 慢播修復結果（已套用）」**。對照紅／青輪廓，再到下一步以正常速度播放整條路線。
5. 覺得自然再按「確認此接點可用」。若不滿意可復原，或標記需修整。原始 PNG 不會被修復覆寫。

每支至少 6 幀，同組須同畫布尺寸。原解析度、各段 FPS、保留範圍的總幀數不變。修復會取代目前頭尾舊幾何對位，保留明暗設定。修改來源、範圍、順序或影像微調後，要重新修復再輸出。

### 多表情怎麼測？

例如 AA-AB → AB-BB → BB-BA → BA-AA，選「順序循環（最後接回開頭）」。依次檢查四個接點，包含 BA-AA → AA-AB；不需要隨機播放。先看正常速度下的比例、表情與明暗，再慢播有疑慮的接點。只需要 A→B→C、不接回 A，改選「播完結束」。

單表情已有維護者實測認可；多表情已完成合成測試，實際素材驗收仍在進行。大幅姿勢變化、遮擋或新增線條仍可能出現重影。

### 「比例待檢查」是什麼？

代表該段比例估計不夠可靠，可能保留原比例，或只完成本段穩定、尚未對齊跨表情的共同尺度。接縫仍可能修復完成；「接點已套用」不代表整段比例也一定通過。請按狀態原因核對畫面，不要為了消掉提示反覆強制變形。

貼邊保護會保留既有覆蓋，接縫可用已觀察到的角色像素補償窄邊緣缺口；不是生成式補畫，不保證補出原素材從未出現的部位。局部呼吸、嘴型與動作不應被當成整體比例漂移強行壓平。

### 比對與進階工具

紅色為 A，青色為 B；差異可能來自位置、輪廓或合理動作，不是每條紅青線都要消除。短播反覆跳回短播起點不等於接縫出錯，請同時看整路線。

「進階：僅分析、不重建影格」保留舊分析、安全套用及未套用候選預覽，供需要時使用。它與一鍵修復的已套用結果不同；詳細舊流程見 [v3.10.3 紀錄](v3.10.3-validation.zh-TW.md)。正常操作不必走這條路。

明暗匹配使用有效 Alpha 區域與固定曲線，不能消除片內逐幀閃爍。工具沒有語義 AI 自動驗收，最終仍以播放觀感為準。

## 7. 先預覽，再輸出

「預覽與輸出」可以先播放**目前草稿路線**，不必先輸出影片。確認順序、每段切換和開放路線的停止位置，再輸出。

輸出成功後會載入**當次實際 PNG 成品**。它有固定版本身分，不會隨後續草稿改動。若輸出期間繼續修改，完成的版本仍是提交輸出當時的設定，請留意草稿已變更提示。

草稿短播與整路線預覽可能縮小以節省記憶體；輸出仍保持原尺寸。需要查原尺寸細節，按「開啟資料夾」查看 PNG。端點像素相同只說明那兩張圖一致，過渡區仍可能扭曲、停頓或改變動作速度。

影片無音軌。輸出包含透明 PNG、透明 WebM 與記錄路線／來源的 manifest。manifest 是資料，不會替遊戲引擎實作播放控制。

## 8. 保存、復原與版本

接點草稿會自動保存到本機專案；固定位置的「儲存」可立即保存。保存失敗會顯示錯誤。**保存設定不會產生新成品。**

「復原／重做」用於本次開啟專案的編輯歷史；一批自動修正可整批復原。重新整理頁面後會載入磁碟草稿，編輯歷史不是長期版本備份。

過期的自動明暗或共同接點會列出「停用過期設定」修復計畫；只有套用時才改變草稿，也能整批復原。有效的舊修正保持原樣。

分析結果綁定當時的草稿及來源。改了順序、參數或來源後，請重新分析。過期的修正計畫會被拒絕，不會套到不同素材。

重跑去背會更新原始去背 PNG；先前影片會標示「來源已更新」。它仍是可查看的歷史成品，沒有自動包含新 PNG，也不再沿用舊透明度驗證作為本次結果。重新合成／輸出後再驗收。缺少來源核對記錄的舊版會標示「來源未核對」。

### 舊單段方案怎麼辦？

舊版的局部保護圈、內部參考幀與特殊漸變不能直接等價轉換。在「進階／相容」入口開啟舊單段方案，沿用原來的渲染規則；不會在升級時改寫。新修整優先使用共用接點工作區。如果想在新流程續作舊成品，明確選它的修整版本作為來源。

### 備份位置

- `jobs/素材資料夾/transparent_png`：原始去背 PNG；舊任務也可能使用 `rgba`。
- `jobs/素材資料夾/loop_edits`：舊單段修整成品。
- `transition_projects/專案ID/project.json`：接點修整草稿。
- `transition_projects/專案ID/repairs`：一鍵修復 PNG 快取；須與專案一起備份，不能只保存 project.json。
- `transition_projects/專案ID/anchors`：共同接點圖，需連同專案保存。
- `transition_projects/專案ID/versions`：每次正式輸出。

要保留可編輯能力，請在處理結束後一起備份相關 jobs 和整個專案資料夾。只備份 project.json 不會包含全部來源圖。

| 現象 | 處理方式 |
| --- | --- |
| 更新後仍是舊版／缺功能 | 後端更新需要重啟服務；不能只重新整理。確認右下角 v3.12.0。 |
| 8767 已被使用 | 先保存、等處理結束並暫停隊列，再執行「重新啟動工作台.cmd」。工具會核對服務身分；不會終止未知程式。 |
| 找不到剛完成的素材 | 在來源區更新清單；確認去背完成。不同任務不會僅因同名就自動替換。 |
| 載入舊版本後草稿不同 | 正常。成品是不可變版本；選擇草稿預覽或重新輸出。 |

| 比例待檢查 | 看第 6 節；不可靠時保留原比例，不代表輸出失敗。 |
| 修正計畫已過期 | 目前草稿或來源已變更，重新分析。 |
| 來源／對位／共同接點過期 | 核對來源，再重新計算相依修正；不要將舊預覽當目前結果。 |
| 自動修正沒有處理所有接點 | 保守規則不確定的項目會保留待檢查；不是輸出失敗。 |
| 輸出提示越界 | 減少過大的位移／縮放，核對紅青輪廓與畫布，再另存新版本。 |
| 預覽超出記憶體限制 | 減少保留幀數或拆小組；不要把未完成載入當播放結果。 |
| WebM 在其他播放器有底色 | 播放器可能不支援 Alpha；與透明 PNG 對照，再確認遊戲引擎支援。 |
| 缺 Python／FFmpeg／模型／節點 | 回到第 1–3 節，依環境檢查的實際錯誤處理。 |

關閉瀏覽器不等於關閉背景服務。不要在輸出中強制停止，也不要開兩個服務同時處理同一個 jobs 資料夾。更完整的安裝、舊版手動控制與檔案格式，見[使用說明](../使用說明.txt)。

## 10. 從舊版升級

先等待工作結束、儲存草稿並備份工具資料夾。將分享包解壓縮至獨立目錄核對，更新原資料夾中的程式與文件；保留 jobs、uploads、transition_projects、batch_queue.json、models 與 repair_runtime.json，不要用空白範本覆蓋個人資料。重跑 setup.cmd 更新工作臺依賴。首次使用 RIFE 需完成模型安裝。

關閉舊服務後啟動更新的工作臺，確認 v3.12.0；可使用「重新啟動工作台.cmd」核對並重啟本資料夾閒置服務。不要同時運行兩份工具處理相同來源。開啟原表情組按「重新修復全部接點」，再另存新輸出；舊成品不會自動更新。
