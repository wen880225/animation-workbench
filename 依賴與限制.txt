動畫去背工作臺 v3.9 — 依賴與限制
文件更新日期：2026-10-05；Qwen 模型授權、ComfyUI 節點與模型放置位置已於本日重新查核。

硬體／平台：此分享版面向 Windows x64 + Python 3.12。
工作臺本身不執行模型；ComfyUI 所需顯示卡、VRAM、RAM 取決於模型與設定。
目前未驗證統一的最低 VRAM，不保證任何顯示卡都可跑。磁碟需同時容納影片、
來源拆幀、透明 PNG 及各次另存結果，長片可能需要大量空間。
同時間限單一去背任務；逐幀生成速度依硬體而異，固定 Seed 不能消除閃爍或變形。
只支援本機 HTTP ComfyUI（localhost / 127.0.0.1）；不支援遠端登入與多人服務。
不要把工作臺連接埠暴露到公網；此版本沒有多人帳號和登入管理。

介面整理（v3.9）：
不新增模型、套件或雲端服務；沿用原有修整、預覽及輸出處理流程。
多段銜接分成素材與順序、統一明暗、修好接點、預覽與輸出四步，僅顯示當步設定。
單段修整分開呈現明暗與參考、首尾循環；換步驟／用途不會清除既有修整。
進階設定預設收起；已套用項目會標示，收起不代表停用，仍會影響預覽與輸出。
固定儲存／復原方便操作，但「儲存方案」不會代替輸出，也不會備份全部來源素材。
使用指南、舒適／大字及配色為本機介面功能，不改素材尺寸、Alpha 或成品。

多動畫共用接點（v3.8）：
沿用既有 OpenCV 光流與 Alpha 預乘合成，不新增生成模型或雲端服務。
使用目前修整後的端點建立不可變 PNG 快照；每個接點獨立，避免全部表情混成一張。
僅支援每段一次的完整循環；每段至少四幀，頭尾過渡各至少兩幀且不能重疊。
支援每邊 8–4096 像素、最多 800 萬像素；光流處理需額外 CPU 時間與記憶體。
完整解析度預覽與輸出共用流程；輸出會核對實際接點 PNG，並保留快照。
來源、明暗、基礎幾何設定及順序改動後需重建，不能把舊基準套進新來源。
端點逐像素相同只驗證位置與外觀，不能保證運動方向、速度或節奏自然。
成品預覽的去重選項只跳過經驗證且 FPS 相同的相鄰端點，並縮短一幀播放時間。
獨立輸出圖序與 WebM 保留全部幀；外部引擎須自行採用相同去重策略。
RIFE 未內建：現成 RGB 補幀不可直接當作透明 PNG 補幀，仍需另行驗證整合。

多段明暗與固定循環（v3.7）：
不新增模型或外部服務；在本機 CPU 對每段最多五張影格的不透明中間調前景抽樣。
每段採固定曲線，避免逐幀自動調整造成新的明暗抽動；不是逐幀去閃爍或局部補光。
純黑、純白與 Alpha 不變；彩色素材仍可能因通道曲線產生色彩變化，請目視檢查。
姿勢、服裝、光源或前景分布不同會影響估計；層次不足時保留設定或要求換參考。
來源、保留幀範圍或單段明暗改變會使校準過期，需重新統一或停用校準。
全局微調在各段校準後套用；草稿預覽與成品輸出使用同一處理流程。
新組播放順序每段一次，舊自訂重複／部分路線會保留；成品以自身 manifest 為準。
輪廓差異檢查 Alpha 外框，不代表內部線條、明暗或運動速度已一致。
這些功能需要 v3.7 後端，刷新頁面不會更新仍在執行的舊服務。

首尾共同基準（v3.6）：
沿用 OpenCV，在本機 CPU 計算首尾過渡，不下載或呼叫生成模型。
過渡處理支援每邊 8–4096 像素、總面積最多 800 萬像素；輸出解析度與幀數固定。
循環至少四幀，開頭與結尾過渡各至少兩幀且不能重疊，基準必須位於所選範圍。
首尾 PNG 像素一致會在輸出後回讀驗證；相鄰動作、速度連續與視覺品質需自行播放確認。
光流估算可能在遮擋、大幅姿勢改變或細節變化時失準，不提供補畫能力。
新功能需要 v3.6 後端；單獨刷新網頁不能更新仍在執行的舊服務。
自動局部對位（v3.5）：
新增 SciPy 1.17.0 及 opencv-python-headless 4.11.0.86，沿用 NumPy 2.3.5／Pillow 10.4.0。
這項對位在本機 CPU 計算，不呼叫 ComfyUI，也不下載生成模型。
每邊尺寸支援 48–4096 像素，總面積最多 800 萬像素。
只適合相似姿勢與小幅輪廓差異；不能補畫缺失內容，也不保證運動速度連續。
啟用時使用局部對位取代手動幾何變形，避免重複重採樣；明暗仍可獨立調整。
對位方案包含可重建的控制資料及來源識別，需連同原始 PNG 一起保留。
來源端點或圖片改變後需重新計算；停用對位可回到原有手動變形。

介面與資料保存：
使用現代桌面瀏覽器操作。「顯示設定」提供六款配色、跟隨系統及舒適／大字；只影響介面。
PNG／WebM 檢查底色及遊戲背景是預覽設定，不會因切換主題而寫入素材。
介面偏好與各任務的單動畫修整草稿放在瀏覽器本機儲存空間；不是雲端同步或檔案備份。
清除網站資料、更換瀏覽器或改用不同網址／連接埠，可能無法恢復該份草稿。
瀏覽器禁止本機儲存時，草稿與偏好無法跨次保存。參考圖重新開頁面需再選取。
需要保存可移動的單段修整設定，請按「儲存方案」，保留任務資料夾中的方案。
播放器可查看已完成的修整版本；逐幀檢查與單動畫再次修整仍以原始去背 PNG 為來源，
不會因播放器切換版本而自動改為對上一版結果繼續加工。
貼邊固定只保留指定側邊的原位置，過渡帶可能拉伸線條；不會修補來源缺圖或自動匹配首尾。
過渡太窄造成折疊會被拒絕；上下及未固定側邊的越界檢查仍然有效。
輸出時間是按已完成工作估算的當前階段剩餘時間，不是保證完成時間。

多動畫銜接：
來源為已完成去背任務或已輸出的修整版本；同一專案必須使用相同寬高的畫布。
每組最多 16 段動畫；輸出至少要有兩段，每段至少兩幀。頭尾漸進區間不能重疊。
各來源版本有自己的幀數範圍與 FPS，不會為了加入專案而自動改變素材解析度。
接點分數是輪廓、外觀與動作的比較線索，不能代替人工確認或保證動畫銜接自然。
不同表情可能有合理的像素差異；位置、縮放與明暗微調無法修復所有生成模型變形。
接點有方向性；A → B、B → A 與 A → A 要分別檢查。片段設定改變後，相關確認失效。
專案與輸出放在 transition_projects；不覆寫來源 PNG，也不包含在乾淨分享 ZIP。
專案設定引用 jobs 中的來源圖序；只備份 project.json 不會同時保存這些來源圖片。
輸出期間若來源被改寫或偵測到畫布越界，輸出會停止，已產生候選檔案仍保留。
接縫短播是草稿預覽；「預覽與輸出」載入成品後讀取實際 PNG，依片尾 → 片頭播放。
任意中途影格切換不在此功能保證範圍內；manifest 不是 Godot 自動匯入器。
一次儲存多段透明 PNG 與 WebM 會增加磁碟用量。成品預覽使用支援 createImageBitmap
縮小解碼的桌面瀏覽器，預覽長邊最多 720 px，再依總幀數調整以符合約 384 MiB
解碼像素預算；若需降到長邊小於 256 px，會停止載入並要求減少幀數或分組。
原圖長邊不足 256 px 時，以原尺寸為下限，不強制放大。
這是預覽像素用量估算，不是整個瀏覽器 RAM 的硬上限，亦非 WebM 檔案大小限制。
預覽尺寸可縮小，原始輸出 PNG／WebM 尺寸保持不變。銜接檢查使用草稿；
要檢查某輸出版本的完整解析度細節，請開啟該版本資料夾查看 PNG。

【v3.2 本機隊列與選區】
隊列狀態儲存在 batch_queue.json，屬於使用者資料，不附在分享包。
同時只處理一支去背任務；與修整匯出共用工作鎖，等待其他處理完成後再派送。
重啟會保留隊列並暫停，不會自行開始耗用 GPU。單支失敗不阻擋後續影片。
局部選區使用同一套固定畫布變形函式做預覽與輸出，不新增模型或外部服務。
幾何變形的零影響區保留原始 RGBA；若另有明暗調整，仍為全畫面操作。
